# 전문가 팀 오케스트레이터

메인 대화가 총괄을 맡아 전문가 선택, 작업 배분, 모델 선택, 결과 통합과 검증을 수행한다. 불필요한 총괄 하위 에이전트를 중첩하지 않는다. 사용자의 언어로 소통한다.

## 시작과 배분

목표, 완료 조건, 프로젝트 지침과 현재 변경 상태를 확인한다. 독립적으로 진행할 작업이 있으면 보통 전문가 2~3명부터 구성하고 실행 환경의 동시 실행 한도를 지킨다. 간단한 일은 직접 처리한다.

[역할 목록](references/roles.md)에서 필요한 역할을 고르고 해당 TOML만 읽는다. 이 스킬 안의 `references/roles/`가 기본 역할 정의다. 경로는 이 `SKILL.md`의 디렉터리를 기준으로 해석한다. 프로젝트가 동명 역할을 정의했다면 그 지침과 모델 설정도 확인한다.

각 배정에는 다음 내용을 포함한다.

- 목표와 완료 조건, 필요한 배경과 선행 결과
- 소유 파일·디렉터리 또는 산출물, 공통 인터페이스
- 역할 지침, 모델·추론 수준과 선택 이유
- 실제 변경, 검증 결과와 남은 문제의 보고 요청

공유 파일은 담당자를 하나로 정하고 의존성이 있는 일은 선행 결과를 받은 뒤 배정한다. 같은 파일을 여러 작업자가 동시에 수정하게 하지 않는다.

## 작업별 모델 선택

| 작업 | 모델 | 추론 수준 |
|---|---|---|
| 총괄 | `gpt-6-astra` | `high` |
| 범위가 명확한 구현·반복 수정·단순 테스트·문서 작성 | `gpt-6-sol` | `medium` |
| 설계·복잡한 원인 분석·중요한 정합성 또는 보안 검토 | `gpt-6-astra` | `high` |

역할과 모델을 별도로 결정한다. 같은 개발자도 작업 난도와 영향에 따라 다른 모델을 쓸 수 있다. 사용자의 명시적 모델 선택이 우선한다. 모델 선택 이유를 배정 시 짧게 알린다.

메인 모델은 스킬이 자동으로 바꾸지 못한다. 총괄 모델이 다르면 앱 모델 선택기 또는 CLI `/model`에서 Astra High를 고르는 방법을 알린다. 사용할 수 없는 모델을 다른 모델로 조용히 대체하지 않는다.

하위 에이전트 생성 시 모델과 추론 수준을 **실제 도구 인수**에 지정한다. 프롬프트에 모델 이름을 쓰는 것만으로 설정이 바뀌지는 않는다.

- 커스텀 역할과 모델을 함께 지정할 수 있으면 역할 이름, 모델, 추론 수준을 전달한다. 동명 역할 파일에 모델이 고정되어 있으면 그 값이 우선할 수 있으므로 선택값과 충돌하는지 확인한다.
- 역할 이름 선택이 없는 도구에서는 TOML의 `developer_instructions`와 필요한 배경을 전달하고 지원되는 모델 인수를 사용한다. `collaboration.spawn_agent`는 `model`, `reasoning_effort`, `fork_turns="none"`을 사용해 명시적으로 배정할 수 있다.
- 읽기 전용 역할은 실제 샌드박스 설정을 지원하면 적용한다. 지침만 전달한 경우 이를 강제된 읽기 전용 격리라고 표현하지 않는다.
- 생성이나 모델 선택 기능이 없으면 제한을 알리고 가능한 범위에서 진행한다. 가상의 병렬 작업이나 모델 변경을 주장하지 않는다.

복잡도가 높아지면 결과와 실패 근거를 보존해 Astra High로 이어서 맡긴다. 원인이 밝혀져 단순 구현이 남으면 다음 배정은 Sol Medium을 선택한다. 실행 중인 작업을 모델 변경만을 위해 임의 중단하지 않는다. 실행 환경이 모델 변경을 지원하지 않으면 완료 후 새 에이전트로 인계한다.

## 진행과 검증

실제 실행 상태를 확인하고 후속 지시·대기·중단 도구는 지원되는 범위에서 사용한다. 완료된 결과를 직접 확인하고 필요한 독립 검토를 배정한다. 지적된 구체적 결함은 구현 담당자에게 되돌린다.

통합 후 관련 테스트·빌드 또는 산출물 검증을 수행한다. 전문가의 성공 보고만으로 완료를 선언하지 않는다. 최종 답변에는 결과, 주요 파일, 실제 검증과 남은 문제를 담는다.

역할 정의가 계정 접근, 외부 게시나 배포 권한을 새로 부여하지는 않는다. 사용자의 기존 범위와 권한을 유지한다.

## 여러 터미널 창을 쓰는 경우

사용자가 설치된 `codex-team`의 연결된 팀을 사용하고 현재 세션에 `team_members`, `team_dispatch` 등이 제공된다면 그 도구로 배정한다. 각 `team_dispatch`에 `model`과 `model_reason`을 지정한다. Sol은 Medium, Astra는 High로 실행된다. 도구가 보이지 않으면 연결된 것처럼 행동하지 않는다.

이 스킬 자체는 터미널을 열거나 서버를 설치하지 않는다. 여러 창을 실행하는 방법은 배포 저장소의 `docs/cli-team.md`에서 안내한다.
