# 역할 목록

필요한 역할의 TOML만 읽는다. 파일의 `developer_instructions`가 역할 지침이며 `sandbox_mode`는 해당 역할의 권한 조건이다.

| 역할 | 담당 |
|---|---|
| [`architect`](roles/architect.toml) | 소프트웨어 구조, 인터페이스, 작업 분할과 통합 순서를 설계한다. |
| [`automation_engineer`](roles/automation-engineer.toml) | 반복 작업용 스크립트, 파일 처리와 도구 연동을 구현한다. |
| [`backend_developer`](roles/backend-developer.toml) | API, 서버 로직, 인증·인가, 외부 연동과 데이터 흐름을 구현한다. |
| [`business_analyst`](roles/business-analyst.toml) | 업무 프로세스, 경쟁 대안, 비용·효과와 사업 가정을 분석한다. |
| [`content_strategist`](roles/content-strategist.toml) | 대상 독자, 핵심 메시지, 콘텐츠 기획과 홍보 문안을 만든다. |
| [`data_analyst`](roles/data-analyst.toml) | 데이터 정리, 탐색, 지표 계산, 시각화와 분석 보고서를 작성한다. |
| [`database_engineer`](roles/database-engineer.toml) | 스키마, SQL, 인덱스, 데이터 무결성과 마이그레이션을 설계·구현한다. |
| [`devops_engineer`](roles/devops-engineer.toml) | 빌드·배포 설정, CI/CD, 컨테이너, 환경 구성과 운영 관측을 다룬다. |
| [`frontend_developer`](roles/frontend-developer.toml) | 웹 화면, 컴포넌트, 상태 관리, 상호작용과 반응형 UI를 구현한다. |
| [`learning_designer`](roles/learning-designer.toml) | 학습 목표, 커리큘럼, 강의안, 실습과 평가 문항을 설계한다. |
| [`orchestrator`](roles/orchestrator.toml) | 필요한 전문가 선택, 작업 배분, 병렬 진행, 통합과 검증을 총괄한다. |
| [`performance_engineer`](roles/performance-engineer.toml) | 응답 시간, 렌더링, 메모리, 번들 크기와 처리량의 병목을 분석한다. |
| [`presentation_designer`](roles/presentation-designer.toml) | 발표 흐름, 슬라이드 구조, 차트와 제안서 시각 구성을 만든다. |
| [`product_manager`](roles/product-manager.toml) | 사용자 요구를 기능 범위, 우선순위, 사용자 스토리와 수용 조건으로 정리한다. |
| [`qa_engineer`](roles/qa-engineer.toml) | 사용자 시나리오를 재현하고 단위·통합·E2E 테스트와 회귀 검증을 수행한다. |
| [`researcher`](roles/researcher.toml) | 공식 자료와 신뢰할 수 있는 출처를 조사해 근거와 불확실성을 정리한다. |
| [`reviewer`](roles/reviewer.toml) | 변경 후 버그, 동작 회귀, 보안 문제와 빠진 테스트를 독립 검토한다. |
| [`security_reviewer`](roles/security-reviewer.toml) | 인증·인가, 입력 처리, 비밀정보 관리와 의존성 보안 위험을 검토한다. |
| [`technical_writer`](roles/technical-writer.toml) | README, API 문서, 설치 안내와 사용자 매뉴얼을 작성한다. |
| [`ux_designer`](roles/ux-designer.toml) | 정보 구조, 사용자 흐름, 화면 구성, 접근성과 디자인 방향을 설계한다. |
